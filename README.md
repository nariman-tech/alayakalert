# SafeNet KZ

Прототип рабочего места аналитика для хакатона SafeNet KZ. Система находит в постах, чатах и
эфирах признаки незаконных розыгрышей (трек 1), скрытой рекламы онлайн-казино (трек 2) и
финансовых пирамид (трек 3), ставит риск 0–100 и объясняет, какие признаки сработали.

Система не объявляет схему незаконной. Она подсвечивает признаки, а решает человек.

## Быстрый старт

Нужен Python 3.10+. Движок работает без внешних библиотек.

```bash
python -m data.generate          # синтетический датасет -> data/cases.jsonl (уже лежит в архиве)
python -m evaluation.evaluate    # метрики -> reports/metrics.md, reports/results.json
python -m app.build              # дашборд одним файлом -> dist/safenet_dashboard.html
```

Откройте `dist/safenet_dashboard.html` двойным щелчком: это полная версия без сервера, кроме проверки своего текста.

Для проверки своего текста запустите сервер:

```bash
pip install -r requirements.txt  # flask, scikit-learn, networkx
python -m app.server             # http://localhost:8000
```

Тесты: `python -m unittest discover tests`.

### Эфиры из сырого текста

Аналитик не получает таблицу ставок — только расшифровку голоса ведущего и сообщения чата.
`engine/transcript.py` сам вытаскивает из текста:

- ставки: «@ник +500», «кинул 1000», «ставлю 2к», «ставка от @ник — 1 000 тг», «@ник 500 салды»;
- победителей: «победитель — @ник», «@ник забирает банк», «жеңімпаз — @ник»;
- правила и приз: «выигрывает только один раз», «бір рет қана ұтады», «разыгрываем банк 150 000 тг».

Формат строк: «[1:20] @ник: текст», время и ник необязательны. Проверка
`python -m evaluation.transcript_check`: все 24 синтетических эфира превращены в сырой текст
(ставки в четырёх стилях), таблицы удалены, разобраны заново — тот же уровень риска в 24 из 24,
ключевые признаки эфира 36 из 36. Оговорка: генератор текста и разборщик писал один автор с одними
и теми же стилями, реальные эфиры разнообразнее — нужна расшифровка настоящего эфира от команды.

### Прогрев перед платными эфирами

Первая стадия схемы, которую наблюдала команда: автор бесплатно переводит деньги «рандомным» зрителям,
а затем зовёт продолжить в Telegram-канале, где начинаются платные эфиры. Сам по себе подарок денег
не нарушение, поэтому признак «Прогрев: деньги случайным зрителям + переход в канал» даёт средний риск
(«стоит проверить»), а вместе с платным участием или «кто последний скинет» — высокий. Пример —
`data/team/observed_warmup_anonymized.txt` (номера и имена заменены на вымышленные).
Отдельно учтено направление денег: «перевожу / отправил / скинул» (автор платит сам) не считается
просьбой перевести деньги на личную карту.

### История аккаунта

Если у аккаунта раньше были бесплатные раздачи, а позже появилось платное участие, к платному кейсу
добавляется признак «Воронка „бесплатно → платно“» с датами как доказательством. В карточке кейса
видна вся история публикаций аккаунта.

## Как устроено

```
engine/
  normalize.py   снимает маскировку: к@зин0, к а з и н о, эмодзи, латинские двойники, транслит
  returns.py     находит обещанную доходность и пересчитывает в годовые
  signals.py     каталог: 41 признак по трём трекам + 5 снижающих факторов
  concepts.py    смысловой слой: сочетания понятий вместо точных фраз, суммы, отрицания
  streams.py     ставки в эфирах: подставные ставки, повторный победитель, сборы против приза
  transcript.py  разбор сырой расшифровки эфира или переписки: ставки, победители, приз, правила
  entities.py    телефоны, карты, промокоды, домены, хэши скриншотов для графа
  scoring.py     прозрачная формула риска и ключевые комбинации
  pipeline.py    кейс -> признаки -> риск -> объяснение; граф связей; «живой» таймлайн
  ml.py          необязательная модель TF-IDF + логистическая регрессия (один признак средней силы)
data/generate.py     генератор синтетики (A — обучение, B — тест в другой манере)
evaluation/evaluate.py   все метрики
app/                 дашборд (один HTML), сервер Flask, офлайн-сборка
```

**Формула риска.** Высокий признак даёт +30, средний +15, низкий +5. Ключевая комбинация
(например, «платное участие + случайный выбор» или «нереалистичная доходность + личная карта»)
поднимает риск минимум до 70. Снижающие факторы вычитаются: предупреждение или новость −45,
официальная лотерея −25, лицензированный финпродукт −25, явно бесплатное участие −20.
Уровни: 0–39 низкий, 40–69 средний, 70–100 высокий. Кейс попадает в выборку при риске от 40.

**Где ИИ, а где правила.** Решение принимает прозрачная формула. ML-модель даёт только один признак
средней силы. На текущих данных она ничего не меняет в итоговых метриках, это честно стоит говорить
на защите. LLM использовать для генерации дополнительной синтетики, а не для вердиктов.

## Метрики на синтетике (тестовая часть, 98 кейсов)

| | Precision | Recall | Ложные срабатывания |
| --- | --- | --- | --- |
| Поиск по словам (≥ 2 ключевых слова) | 87% | 39% | 7% |
| SafeNet KZ | 98% | 92% | 2% |

- Стресс-тест маскировки: словарь падает с 39% до 6% recall, SafeNet — с 92% до 85%.
- Скорость обнаружения: высокий риск в среднем на 2,8-м сообщении (26% разговора); все 18 чатов
  пирамид помечены до первого «скриншота выплаты».

### Два цикла улучшений

**v1.** Система ждала подробных постов с цифрами, а реальные сообщения короткие. Добавлены признаки
для коротких сообщений: денежная приманка, «заплати — получишь больше», личное сообщение о «выигрыше»,
плата за вывод, доход из взносов новых участников, обещание дохода, казахские формулировки,
снижающий фактор для обсуждений и статей. Слепой результат v1 на наборе 3 — 5 из 15.

**v2.** Вывод из набора 3: правила слишком зависели от знакомых формулировок. Поэтому вместо новых фраз
добавлен смысловой слой `engine/concepts.py`: признак срабатывает, когда в одном сообщении встречаются
нужные понятия (оплата → выгода → «больше»; вывод + доплата + условие; участие + сумма; приглашение +
выгода + взносы), каждое понятие — словарь синонимов на русском, казахском и транслите, в любом порядке
слов. Добавлены единый распознаватель сумм («2к», «2 тыс», «2 тис», «2 мың», «2 000 ₸») и учёт
отрицаний («никаких гарантий нет», «без взноса»). Проверка на 25 провокационных честных сообщениях
сначала дала 6 ложных срабатываний — правила сужены до 0.

Что это доказывает и что нет: рост на наборах 1–3 показывает, что ошибки исправлены, но не доказывает,
что система научилась новым формулировкам — эти тексты использовались для исправлений. Это покажет
только набор 4.

### Как проводится слепая проверка набора 4

1. Команда присылает **только тексты, без ответов**.
2. Система ставит оценки командой `python -m evaluation.team_check --predict texts.tsv reports/set4_predictions.tsv`,
   файл оценок сохраняется в истории изменений (git) **до** получения ответов.
3. Команда присылает ответы, сверка: `python -m evaluation.team_check --score reports/set4_predictions.tsv labels.tsv`.
4. Правила после этого не меняются. Публикуются precision, recall, F1 и число ложных срабатываний.

Версии зафиксированы в git: тег `v1` (отпечаток движка `867baa09ac38`, результат набора 3) и тег `v2`
(отпечаток `436e686578bc`, для набора 4). Отпечаток: `cat engine/*.py | sha256sum`, первые 12 символов.

Фишинг (коды из SMS, «звонок из банка», поддельные eGov) не входит в три трека хакатона и пока не
ловится — это следующий модуль в плане развития.

- Сеть связей: найдена спрятанная сеть из 21 аккаунта во всех трёх треках (один телефон организатора,
  один скриншот «выплаты», один «победитель» эфиров) и сеть из 8 блогеров с одним промокодом.

Полный отчёт: `reports/metrics.md`.

### Честные ограничения

- Данные синтетические. Тестовая часть написана в другой манере (сленг, казахский, транслит), но тем же
  автором, что и правила. Одна ошибка разбора казахского порядка слов исправлена после того, как
  всплыла на примере, — тестовая часть уже не полностью «слепая».
- Честных текстов всего около 220 (133 синтетических, 60 командных, 25 провокационных), и часть из них
  использовалась для исправлений. Этого мало, чтобы утверждать, что система не обвиняет невиновных
  на реальном потоке.
- Слабое место — сплошной транслит: на синтетике найдено меньше половины замаскированных транслитом кейсов.
- Сетевые признаки и ML в режиме «живой эфир» не используются: там видно только то, что уже прозвучало.

## Что делать дальше (по ролям)

**Движок.** Разобрать пропуски из `reports/metrics.md` («мест по 2 000 тг», «Каспи +7…» без «на»,
«рандомом», «кладёшь … забираешь», казахское «сіз PlayStation 5 ұтып алдыңыз»). После правок —
только перепроверка на новой тестовой выборке. Усилить транслит.

**Данные.** Новая тестовая выборка от другого автора. Ещё трудные честные примеры: реклама
лицензированных букмекеров, розыгрыши магазинов, инвестиционные блоги с реальной доходностью.

**Интерфейс.** Прогнать демо на ноутбуке для защиты в обоих режимах (сервер и офлайн-файл).
Записать видео «живого эфира» на случай сбоя.

**Питч.** Демо: очередь → карточка эфира-аукциона → живой эфир (риск становится высоким на 2-м
сообщении) → граф «одна сеть — три схемы» → метрики со стресс-тестом. Источники цифр — в плане команды.

## Этика

Только синтетические данные: аккаунты, номера (+7 700 000 …), карты (4400 43** …), домены и бренды
вымышлены. Схемы — по мотивам открытых новостей о казахстанских кейсах 2025–2026 годов.
Система помечает признаки для ручной проверки и не помогает организовывать схемы.
